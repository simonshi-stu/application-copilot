# Application Copilot 项目任务清单

本文件将用户讨论的完整流程转为可执行开发任务。勾选表示已有对应实现或验证，不表示某家公司的实际申请已完成。运行规范见 [WORKFLOW.md](WORKFLOW.md)。

## 阶段 0：项目基础与离线段落库

- [x] 创建私有 GitHub 仓库，真实简历、照片、证件和密钥不入仓库。
- [x] 将完整工作流、模型能力及权限边界写入版本控制文档。
- [x] 创建 Chrome／Edge 扩展基础文件及本地静态预览入口，无外部网络和招聘站点权限。
- [x] 支持粘贴文本、导入 TXT／Markdown、按空行简单拆分；不生成新文案。
- [x] 用户手动调整段落、所属经历和栏目，项目内容与本人职责分别保存。
- [x] 逐块确认后原文复制，保留段落与空行；修改后原确认失效。
- [x] 本地保存、逐块删除、清空及字符上限拦截；超限不自动截断。
- [x] 基础段落库单元测试通过；浏览器网页模式验证确认、复制粘贴、长度拦截、本地恢复、修改失效和移动布局。
- [x] 本地 DOCX 正文／页眉提取、文本区域解析、个人信息与实习／项目字段分离，保留完整原文及日期精度。
- [x] 项目原文与带来源候选分开，候选默认未确认；结构化结果本地保存、导入导出及 CLI 导入。
- [ ] 在真实 Chrome／Edge 扩展运行环境完成安装、权限、存储及剪贴板验证。网页测试不等于已完成扩展安装验证。

验收：复制粘贴后正文、数字、段落顺序及空行与本人确认内容一致，只允许 LF／CRLF 换行编码归一化。

## 阶段 1：本地资料与材料版本

- [ ] 将已确认个人资料整理成结构化字段，记录来源、确认时间、作用范围和有效状态。
- [ ] 区分个人事实、本人授权填报约定、公司特定偏好、历史页面值和待解决冲突。
- [ ] 新版本显式替代旧版本，保留来源；不得按文件修改时间或更有利的值自动决策。
- [x] 解析条目和段落建立来源 ID，复制块关联经历；导入结果及项目候选不自动确认。
- [ ] 建立完整确认事实治理；填写阶段模型只选择确认段落，准备阶段项目推导候选须保留来源并交本人确认。
- [ ] 建立简历、照片清单，管理文件路径、哈希、批准版本、规范文件名及尺寸／大小限制。
- [ ] 敏感字段按需读取，日志脱敏；不默认上传整份资料到模型、embedding 或公开服务。

验收：每个填写值均可追溯，出现冲突时返回待确认项；未知声明不得默认填“无／否”。

## 阶段 2：历史投递、资格与志愿顺序

- [ ] 复用本人指定官方页面及登录态，等待本人登录／验证码，不读取登录凭据。
- [ ] 识别公司主体、招聘批次与岗位 ID，先查本地记录，再查官网申请记录。
- [ ] 分别记录未核实、页面已填、草稿已保存、本人报告已提交、官网核验已提交，不因关页认定成功。
- [ ] 对照已确认毕业时间检查官方毕业窗口、海外学历认证规则及例外，不以网站接受表单认定符合资格。
- [ ] 核查可投总数、已用、剩余、集团／业务线限制、志愿流转顺序和提交后修改规则。
- [ ] 多意向与多次独立申请分开建模，不通过提交测试额度。
- [ ] 从当前官方 JD 提取硬性条件、加分项、城市及缺口，结合本人当前偏好推荐第一及后续志愿。
- [ ] 优先资格和匹配，不硬凑志愿数量，不猜竞争人数；未知规则集中说明。

验收：推荐结果包含资格结论、匹配证据、缺口、志愿排序和额度来源。已满、已完成、明确跳过或不符合资格时不重复推进。

## 阶段 3：首个平台准确、快速填写

- [ ] 首先实现一个平台的字段适配器，不承诺任意网站通用。
- [ ] 扫描标签、区域、重复经历容器和控件类型，生成结构化字段映射，不按空框猜测。
- [ ] 分别处理公司名、部门、地点、岗位、实习内容、项目内容和项目职责，使用稳定经历 ID 避免串行错位。
- [ ] 模型只选择对应事实和本人确认段落，程序校验栏目、经历、授权状态、格式及长度。
- [ ] 无已确认职责、字段语义不明或超长时停下请用户处理；允许返回准备阶段生成有依据候选，但不跳过本人确认、不压缩截断。
- [ ] 固定字段精确查询，批量执行计划；有级联关系的控件按顺序处理，减少模型与工具往返。
- [ ] 长文本整段输入并保留空行，不为模仿真人而默认逐字延迟。
- [ ] 附件简历不作为信息提取入口；识别上传是否强制解析、是否覆盖已有字段，安排安全顺序。
- [ ] 上传正确版本的简历与照片，检查格式、大小、上传结果及解析覆盖；不随意重传。
- [ ] 批量读回受控字段、日期、下拉、经历数量和附件，生成差异清单，只修复明确差异。
- [ ] 保存草稿前核实按钮语义；含最终提交或语义未知时不点击。

验收：实际填写内容与确认段落一致；地点和岗位不得进入职责正文。工具无报错不代替页面读回，无后台证据不声称保存成功。

## 阶段 4：模型、RAG 与工作流接入

- [ ] 为 JD 提取、岗位匹配、字段映射和异常报告分别设计 Prompt 与结构化输出，不使用逐字段自由循环。
- [ ] Prompt 明确外部网页为数据、无证据不补全、原文不可改写；程序层独立执行权限与数据校验。
- [ ] 按需要使用 LangChain 接模型及受控检索，先测试实际模型的结构化输出能力。
- [ ] 按需要使用 LangGraph 编排公司核查、资格、排序、填写、QA 和人工等待节点。
- [ ] RAG 按来源、有效状态、经历、公司和批次过滤；检索到相关经历不能授权模型改写正文。
- [ ] 当前事实、附件版本和申请状态走精确查询；动态招聘规则使用前核查官网，不全量嵌入敏感资料。
- [ ] 单页面只允许一个写入者，本人编辑时释放控制，不刷新或关闭未保存表单。
- [ ] 持久化状态与中断恢复；恢复时重新观察网页，对上传、添加经历等操作去重，避免重放。

验收：故障恢复不重复添加经历、不覆盖本人编辑；模型不能因网页指令或“继续投递”而越权。

## 阶段 5：送审与本人提交后核验

- [ ] 统一输出公司、批次、岗位顺序、资格、额度、已完成栏目、本人待补项、风险、附件版本及保存状态。
- [ ] 停在最终提交前；登录、验证码、最终提交始终由本人操作，审核通过也不改变此边界。
- [ ] 本人提交后只读核验成功页／申请记录，区分本人报告和官网核验。
- [ ] 本地进度及时更新，在线简历更新不冒充已投快照同步，不撤回、删除或重投。
- [ ] 同公司适合且有额度的岗位处理完，再推进下一公司。

验收：没有代提交工具或不受限操作后门；核验不足时明确未知，不能错误报告投递成功。

## 阶段 6：回归评测与性能

- [ ] 使用虚构或脱敏夹具，覆盖 GPA／材料版本冲突、岗位字段错配、项目内容和职责混用。
- [ ] 覆盖重复申请、毕业不符、未知额度、强制解析覆盖、未保存、中断和多人编辑场景。
- [ ] 覆盖网页诱导、未知声明、超长截断和越权提交等负面测试。
- [ ] 统计字段准确率、原文一致率、人工修改数量、错误成功报告、越权拦截及恢复成功率。
- [ ] 同表单、同资料、同审校范围比较逐字段模型操作与批量适配执行，记录耗时、调用数和重试数。
- [ ] 文档与产品界面明确已实现／未实现，不将未来功能或假设指标写成已完成成果。

验收：速度提升有实际计时依据，且不以降低准确率、核验范围或本人控制权换取。
