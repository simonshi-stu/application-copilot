# Application Copilot 设计说明（通用本地投递平台）

本文件描述产品的通用设计，不绑定特定求职者。**当前已有资料整理工作台、复制清单和可选 AI 检查，不是完整自动投递平台。**

2026-10-26 更新：目标调整为“链接与内推码进入任务池 → 本人登录 → 返回 1～3 个岗位 → 本人选择与排序 → 自动填写和独立 review → 集中处理问题 → 本人提交”。优先以 OpenChamber 扩展提供内嵌交互，不要求日常手动打开 localhost。完整目标、弹窗、模型路由和验收边界以 [WORKFLOW.md](WORKFLOW.md) 为准；现有模块见 [ARCHITECTURE.md](ARCHITECTURE.md)。本次仅更新设计，不授权直接实施全部功能。

保留原生 JavaScript 和现有简历解析、确认与原文复制；不迁移 React，不自动安装扩展或更改全局账户配置。网站执行、任务池编排、问题恢复和多角色模型路由尚未实现。

## 0. 定位与硬边界

本地优先：基础资料整理可独立使用；目标自动化通过 OpenChamber／OpenCode 和受控浏览器工具完成。云模型只接收本人授权的最少必要资料；远程宿主与浏览器自管存储须明确披露，不能笼统宣称全部资料永不离开本机。

1. 不代登录、不代验证码、不代最终提交；"继续投递"≠授权提交。
2. 填写只用本人确认文本（原文复制，不改写、不截断）。
3. 未知不编造；冲突挂起待核；不确定不默认"无/否"。
4. 已投不撤回、不重投；页面已填≠已保存≠已提交≠官网核验。
5. 仓库只有代码与虚构测试数据；真实资料、密钥不进 Git。

## 1. 目标用户与场景

- 输入五花八门：群消息、文档表格、纯链接列表、单个链接+码。
- **没有内推信息的用户也能用**：缺码、缺链接的条目照常建档，流程自适应。
- 规则解析优先本地。未来模型按检索、执行、review 分配，由本人选择和授权，不因当前编码会话可用某模型就默认允许业务资料外发。
- 输入链接和可选内推码即可建立公司任务；不必先逐家公司手工整理。首次运行前仍需要足够的已确认个人资料。

## 3. 粘贴导入与类型识别（原型与目标）

### 3.1 处理链

```text
粘贴杂乱文本
→ 拆分出 N 家公司（编号、【】标题行）
→ 每条识别：公司名 / 链接 / 内推码 / 渠道提示 / 批次 / 截止日期
→ 自动判定公司类型（置信度 + 依据）
→ 按类型生成"待补充信息卡"
→ 用户确认/修改 → 本地保存
```

**平台 ≠ 类型**：Moka / 飞书 / 北森（zhiye）/ hotjob / 51job 等是申报系统（决定填写方式）；银行 / 车企 / 制造 / 互联网 / 快消 是类型（决定问什么、核查什么）。两者分开存储。

下一阶段进一步区分行业、企业性质、岗位方向与招聘系统；「国企」不是行业，「运营」不是公司性质。未知不推定；类型只影响可能字段提示，不代替当前 JD／表单的实际要求。界面已按这些维度分开字段。

### 3.2 解析字段与规则

| 字段 | 规则示例 |
|---|---|
| 公司名 | 【】内文字；编号行标题；清理"新增/秋招/20xx 届/投递链接"等后缀 |
| 链接 | URL 正则 + 常见短链（dwz.cn、wxmpurl.cn、s.51job.com…）；按域名归平台 |
| 内推码 | `recommendCode=`/`acotycoCode=` 参数、`内推码:` 文字码、括号提示码 |
| 渠道提示 | 校园大使/大使推荐、员工内推/内部推荐、链接自带、点击链接即可 |
| 批次/截止 | 20xx 届、秋招/春招/提前批/正式批；"X 月 X 日截止" |
| 原文 | 每个条目的原始片段完整保留（rawSource），可回溯 |

### 3.3 类型识别（多信号打分）

| 类型 | 识别信号（示例） | 信息卡重点 |
|---|---|---|
| 银行/金融 | 银行/证券/保险/基金；bank 域名 | 家庭社会关系、奖惩、征信声明、意向分行 |
| 车企/智驾/机器人 | 汽车/智驾/自动驾驶/机器人/激光雷达 | 驾照、出差驻场、海外派遣、意向城市数 |
| 制造/国企/央企 | 集团/重工/钢铁/能源/电气；"中核/中电/中铁"等 | 政治面貌、户籍档案、政审体检 |
| 互联网/科技 | 科技/网络/信息/软件/游戏 | GitHub/作品集、游戏经历（必须问）、期望薪资 |
| 快消/运营/零售 | 食品/饮料/服饰/零售/快消 | 英语成绩、海外经历/签证、轮班接受度 |
| 其他/自定义 | 无匹配 → 通用卡 | 调剂、到岗、薪资、内推绑定 |

打分：已知公司名单 +3；名称关键词 +2；域名特征 +1。界面只展示匹配依据、来源与备选，不展示未经校准的百分比；用户选择会本地记住。
- ≥3 高置信默认选中；1–2 显示置信度与备选；0 → 通用卡。
- **依据随行展示**（为什么判成这个类型），可审计。
- **用户纠正本地学习**：修改一次即记住（别名表，仅本机），下次秒判。
- 一司多类型时列出主/备选，不硬选。

### 3.4 信息卡（集合差）

已实现：只有段落库中确认过的段落计入「已确认可复用」；已解析但未确认的简历内容只列「已识别待确认」；没有资料时不显示任何可复用项。

```text
信息卡 = 类型模板字段 ∪ 公司手动补充 − 资料库已有（将直接复用）− 本表单不适用
```

卡片展示四组：**已确认可复用／已识别待确认／待本人补充／需官网核实**；另有折叠的「部分单位可能要求」提示（不会提前收集敏感信息）。公司特定回答不因为同行业而跨公司复用。

### 3.5 异常与缺失处理

| 情况 | 处理 |
|---|---|
| 无内推码 | 照常建档，码留空；不编造 |
| 多个不同内推码 | 已实现：候选及来源全部保留，选定值留空；必须手动选择或选「本次不用内推」 |
| 只有公司名 | 已实现：纯公司名列表逐条建档并提示待补链接 |
| 同公司多链接 | 全部保留（apply / referral / doc 类型提示） |
| 重复粘贴 | 按"公司名+首个链接"跳过；仅名单级去重，不代表跨批次或岗位申请去重 |
| 纯说明文字 | 不生成条目，计入"忽略说明 N 段" |

### 3.6 速度与准确性

- 解析与识别是**纯本地同步函数**，粘贴即出结果（无网络等待）。
- 识别结果默认是草稿；界面区分草稿／待核对／已人工确认，内推绑定与投递结果另有独立标记，均不代替官网核验。
- 冲突与低置信显式标出，不隐藏。
- 后续任何 LLM 兜底都必须异步、可关闭、标注来源，且不阻塞首屏。

## 4. 字段分级（已实现基础版）

三种级别在界面上的落点：资料库字段（新增或从简历导入后逐项确认，确认才计入「已确认可复用」）；公司确认卡（详情页逐公司问答，仅该公司与本批次）；需官网核实项（列在信息卡中，由本人到官网核对）。

| 级别 | 定义 | 示例 |
|---|---|---|
| A 可直接复用 | 资料库已确认，不再逐公司问 | 姓名、教育、实习、项目、语言、技能 |
| B 每公司询问 | 逐公司确认，不跨公司沿用 | 内推码/渠道、亲属任职、证书编号、调剂/派遣/薪资/到岗、历史声明、证明人、特殊资格 |
| C 来源核实 | 官网/材料核对 | 毕业窗口、官网历史与额度、码绑定状态、附件版本、按钮语义 |

回写机制：询问卡（一次问完）→ 本人回答 → 公司确认卡（字段/回答/日期/来源/适用范围）→ 同步资料库。

## 5. 三遍质检（设计，未实现）

- **遍1 AI 填写**：字段计划 → 附件一次性上传 → 短字段批量 → 长文本分段填+读回 → 日期控件真实读回 → 脚本校验 → 作业单。
- **遍2 独立复核**：本人配置的 review 模型、独立上下文；对照资料库+确认卡+JD+真实页面读回逐栏核对；长文 diff；幻觉扫描；只读输出问题 → 与填写问题合并后集中弹窗。需要修复时交回唯一执行者，不能两个 Agent 同时写页面。
- **遍3 用户终审**：送审单 → 本人检查修改 → 本人提交 → 只读核验记录。

普通缺失／语义疑问／超长只挂起相关字段，先填其他安全内容；填写和 review 尽量完成后一次询问。本人补充后仅重跑受影响步骤。登录、验证码、权限与安全风险立即暂停相关操作；网站强制必填阻断下一页时如实报告未访问区域，不假称所有内容均已检查。

检查点：G0 资料附件 → G1 资格/历史/额度 → 本人选岗位并排序 → G2 字段计划 → G3 填写与保存后 → 集中处理问题 → G4 送审与提交后；任一步不通过：修复或降级待核。

## 6. Agent 分工与外置记忆（设计）

| 角色 | 负责 | 不负责 |
|---|---|---|
| 检索角色（本人可选 DeepSeek 等） | 官方公司与 JD 检索、资格及缺口分析、返回 1～3 个可选岗位 | 不凑足岗位数、不替本人确定最终志愿、不把检索失败当没有岗位 |
| 执行角色（本人可选 DeepSeek 等） | 字段映射、选择确认资料、按批准计划受控填写、记录问题 | 不改写确认文案、不代登录／验证码／提交、不逐字段自由循环 |
| review 角色（本人可选 GPT 等） | 独立上下文对照实际读回、资料及 JD，输出差异、风险和待确认项 | 不与执行者同时写表单，不把缺失读回或失败当通过 |
| 程序编排与校验 | 任务状态、页面写锁、模型配置快照、权限检查、原文 diff、问题持久化与恢复 | 不靠 Prompt 作为唯一权限边界，不以会话结束代表任务成功 |
| 本人 | 登录／验证码、岗位选择与优先级、汇总问题处理、终审、提交 | 审核通过不授权代理代提交 |

原则：**文件是记忆，聊天上下文只是工作区**；写操作串行、单表单单写入者；只读检索可并行；防幻觉四件套 = 外置记忆 → 分段+即时读回 → 交叉模型复核 → 脚本硬校验。

用户已确认补充：主流程必须固化为程序状态机，不能仅把说明写进聊天上下文。私有资料结构化后按字段、经历和用途精确查询；程序缓存有效版本，不反复重读完整记忆。公司与岗位结果写持久化台账，顺序队列由程序在公司完成后推进，不交给模型凭记忆决定。

模型角色是固定职责，不硬编码具体型号。本人填写／选择提供商与精确模型标识，执行前保存配置快照；不可用或超预算时待处理，不静默换模型或提高费用。候选推荐须等本人选定再填写，完整路由和问题规则见 WORKFLOW.md。

## 7. 状态追踪与去重（设计）

- 状态机：待完成 → 待本人登录 → 检索中 → 待本人选岗位并排序 → 填写中 → review 中 → 待本人集中处理 → 待本人提交 → 本人报告已提交 → 官网核验成功；旁路：待补资料／检索受阻／暂停／失败／跳过／额度已满。补充后返回受影响步骤，不整段重放。
- 去重主键：申请人 + 公司主体 + 批次 + 官方岗位ID；不同链接进同一岗位=一次申请；"链接带码"≠已绑定；内推码≠岗位ID。
- 额度组：同一集团/业务线共享名额时单独建模（按用户实际情况）；本地草稿只算"计划占用"。
- 证据映射：页面已填=读回快照；草稿=保存提示/记录页；本人提交=本人说明；官网核验=记录读取。
- 展示结果：“已投递：岗位名”（标明本人记录／官网核验）、“未投递：没有符合职位”；检索失败和部分岗位完成另有状态，不混用。结果由台账生成，不靠模型回忆聊天。
- 默认顺序公司队列：处理完当前公司全部已选岗位后自动进入下一家，可靠确认无合适岗位也自动推进；待本人提交不算完成，登录／验证码／最终提交仍由本人执行。推进范围、核验状态及挂起规则见 WORKFLOW.md 第 9 节。

## 10. 测试策略（从简原则）

- MVP 只保留轻量冒烟测试（解析/判型/信息卡/段落库/DOCX 主路径），防止纯函数回归。
