# Application Copilot 设计说明（通用本地投递平台）

本文件描述产品的通用设计：任何求职者都可以导入自己的简历、资料、公司清单后使用。**当前实现为 MVP**（段落库、简历解析、公司与清单导入），其余模块在设计阶段；实现状态以 [TASKS.md](TASKS.md) 为准。

## 0. 定位与硬边界

本地优先、可独立运行：不依赖任何 Agent 工具；数据只保存在用户本机。

1. 不代登录、不代验证码、不代最终提交；"继续投递"≠授权提交。
2. 填写只用本人确认文本（原文复制，不改写、不截断）。
3. 未知不编造；冲突挂起待核；不确定不默认"无/否"。
4. 已投不撤回、不重投；页面已填≠已保存≠已提交≠官网核验。
5. 仓库只有代码与虚构测试数据；真实资料、密钥不进 Git。

## 1. 目标用户与场景

- 输入五花八门：群消息、文档表格、纯链接列表、单个链接+码。
- **没有内推信息的用户也能用**：缺码、缺链接的条目照常建档，流程自适应。
- 模型（可选，BYOK）只做辅助理解；规则解析与全部存储均为本地。

## 3. 粘贴导入与类型识别（已实现 MVP）

### 3.1 处理链

```text
粘贴杂乱文本
→ 拆分出 N 家公司（编号、【】标题行）
→ 每条识别：公司名 / 链接 / 内推码 / 渠道提示 / 批次 / 截止日期
→ 自动判定公司类型（置信度 + 依据）
→ 按类型生成"待补充信息卡"
→ 用户确认/修改 → 本地保存
```

**平台 ≠ 类型**：Moka / 飞书 / 北森（zhiye）/ hotjob / 51job 等是申报系统（决定填写方式）；银行 / 车企 / 制造 / 互联网 / 快消 是类型（决定问什么、核查什么）。两者分开存储。

### 3.2 解析字段与规则

| 字段 | 规则示例 |
|---|---|
| 公司名 | 【】内文字；编号行标题；清理"新增/秋招/20xx 届/投递链接"等后缀 |
| 链接 | URL 正则 + 常见短链（dwz.cn、wxmpurl.cn、s.51job.com…）；按域名归平台 |
| 内推码 | `recommendCode=`/`acotycoCode=` 参数、`内推码:` 文字码、括号提示码 |
| 渠道提示 | 校园大使/大使推荐、员工内推/内部推荐、链接自带、点击链接即可 |
| 批次/截止 | 20xx 届、秋招/春招/提前批/正式批；"X 月 X 日截止" |
| 原文 | 每个条目的原始片段完整保留（rawSource），可回溯 |

### 3.3 类型识别（多信号打分）

| 类型 | 识别信号（示例） | 信息卡重点 |
|---|---|---|
| 银行/金融 | 银行/证券/保险/基金；bank 域名 | 家庭社会关系、奖惩、征信声明、意向分行 |
| 车企/智驾/机器人 | 汽车/智驾/自动驾驶/机器人/激光雷达 | 驾照、出差驻场、海外派遣、意向城市数 |
| 制造/国企/央企 | 集团/重工/钢铁/能源/电气；"中核/中电/中铁"等 | 政治面貌、户籍档案、政审体检 |
| 互联网/科技 | 科技/网络/信息/软件/游戏 | GitHub/作品集、游戏经历（必须问）、期望薪资 |
| 快消/运营/零售 | 食品/饮料/服饰/零售/快消 | 英语成绩、海外经历/签证、轮班接受度 |
| 其他/自定义 | 无匹配 → 通用卡 | 调剂、到岗、薪资、内推绑定 |

打分：已知公司名单 +3；名称关键词 +2；域名特征 +1。
- ≥3 高置信默认选中；1–2 显示置信度与备选；0 → 通用卡。
- **依据随行展示**（为什么判成这个类型），可审计。
- **用户纠正本地学习**：修改一次即记住（别名表，仅本机），下次秒判。
- 一司多类型时列出主/备选，不硬选。

### 3.4 信息卡（集合差）

```text
信息卡 = 类型模板字段 ∪ 公司手动补充 − 资料库已有（将直接复用）− 本表单不适用
```

卡片展示三块：**需你补充**（逐公司确认）/ **将直接复用**（资料库取用）/ **需官网核实**（毕业窗口、额度、绑定状态等）。

### 3.5 异常与缺失处理

| 情况 | 处理 |
|---|---|
| 无内推码 | 照常建档，码留空；不编造 |
| 多个不同内推码 | 双候选保留 + ⚠ 冲突标记，**不自动选定**，等待人工核实 |
| 只有公司名 | 保留条目 + "未识别链接"警告，用户可补充 |
| 同公司多链接 | 全部保留（apply / referral / doc 类型提示） |
| 重复粘贴 | 按"公司名+首个链接"去重，重复自动跳过 |
| 纯说明文字 | 不生成条目，计入"忽略说明 N 段" |

### 3.6 速度与准确性

- 解析与识别是**纯本地同步函数**，粘贴即出结果（无网络等待）。
- 所有识别结果只是草稿：**用户确认/修改后才算数**；修改自动保存。
- 冲突与低置信显式标出，不隐藏。
- 后续任何 LLM 兜底都必须异步、可关闭、标注来源，且不阻塞首屏。

## 4. 字段分级（通用机制，待实现资料库）

| 级别 | 定义 | 示例 |
|---|---|---|
| A 可直接复用 | 资料库已确认，不再逐公司问 | 姓名、教育、实习、项目、语言、技能 |
| B 每公司询问 | 逐公司确认，不跨公司沿用 | 内推码/渠道、亲属任职、证书编号、调剂/派遣/薪资/到岗、历史声明、证明人、特殊资格 |
| C 来源核实 | 官网/材料核对 | 毕业窗口、官网历史与额度、码绑定状态、附件版本、按钮语义 |

回写机制：询问卡（一次问完）→ 本人回答 → 公司确认卡（字段/回答/日期/来源/适用范围）→ 同步资料库。

## 5. 三遍质检（设计，未实现）

- **遍1 AI 填写**：字段计划 → 附件一次性上传 → 短字段批量 → 长文本分段填+读回 → 日期控件真实读回 → 脚本校验 → 作业单。
- **遍2 独立复核**：另一模型/另一次运行、独立上下文；对照资料库+确认卡+JD 逐栏核对；长文 diff；幻觉扫描；能机械补的补，其余升级为询问卡 → 复核报告。
- **遍3 用户终审**：送审单 → 本人检查修改 → 本人提交 → 只读核验记录。

检查点：G0 资料附件 → G1 资格/历史/额度 → G2 字段计划 → G3 填写与保存后 → G4 送审与提交后；任一步不通过：修复或降级待核。

## 6. Agent 分工与外置记忆（设计）

| 角色 | 负责 | 不负责 |
|---|---|---|
| 强模型 | 匹配排序、冲突判断、遍2 复核、异常解释 | 不逐字段调用；不改写确认文案 |
| 便宜模型 | 字段映射、JD 提取、遍1 批量填写、询问卡 | 不做终审决策、不代提交 |
| 脚本 | 必填扫描、格式/长度/数字校验、读回 diff、去重与额度查询、日志 | 不做语义判断 |
| 本人 | 登录/验证码、B 类回答、终审、提交 | — |

原则：**文件是记忆，聊天上下文只是工作区**；写操作串行、单表单单写入者；只读检索可并行；防幻觉四件套 = 外置记忆 → 分段+即时读回 → 交叉模型复核 → 脚本硬校验。

## 7. 状态追踪与去重（设计）

- 状态机：待核查 → 等待本人登录 → 核查中 → 填写中 → 待本人审核提交 → 本人报告已提交 → 官网核验成功；旁路：待补资料/规则待核/待修复/跳过/额度已满。
- 去重主键：申请人 + 公司主体 + 批次 + 官方岗位ID；不同链接进同一岗位=一次申请；"链接带码"≠已绑定；内推码≠岗位ID。
- 额度组：同一集团/业务线共享名额时单独建模（按用户实际情况）；本地草稿只算"计划占用"。
- 证据映射：页面已填=读回快照；草稿=保存提示/记录页；本人提交=本人说明；官网核验=记录读取。

## 10. 测试策略（从简原则）

- MVP 只保留轻量冒烟测试（解析/判型/信息卡/段落库/DOCX 主路径），防止纯函数回归。
- 全部测试数据为虚构示例；真实内容永不进仓库。
- 真正的验证方式：用户在实际页面上试用，检查布局、解析与判型准确度，再按反馈迭代。
- 框架成熟后再扩充 fixtures 与指标（解析准确率、类型接受率、耗时、填写 diff 通过率），须实测记录，不预设数字。
