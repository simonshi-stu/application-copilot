# 网申工作流与验收边界

更新：2026-10-26。用户已确认任务池驱动、OpenChamber 内交互的产品方向，并补充固定程序流程、私有结构化资料、持久化投递结果和公司顺序队列。**方向确认不是自动化已完成的声明，也不构成一次实施全部功能的授权**。现有产品仍以资料整理、复制清单和本地数据检查为主。

## 0. 新的主流程：交链接，选岗位，最后一起处理问题

```text
粘贴公司链接和可选内推码
→ 进入任务池
→ 本人登录招聘官网
→ 检索官方招聘信息、资格、历史与额度
→ 返回 1～3 个合适岗位（不足 3 个不凑数）
→ 本人选择岗位、确认优先级
→ 按顺序填写已确认资料，跳过并记录不确定字段
→ 程序读回核对 + 独立模型自动 review
→ 集中展示未填项、疑问和差异，一次补充
→ 只重跑受影响部分并复核
→ 本人终审、本人提交
→ 只读核验记录
→ 本公司所选岗位均处理完毕，自动取队列下一家公司
```

- 公司任务与岗位申请分开：一家公司可以有多个候选岗位，但推荐 3 个不代表有 3 次申请额度。本人选择和排序后，仍须遵守官网志愿及共享额度规则。
- 已有资料库用于匹配；没有足够的已确认资料时标记“待补资料”，不编造匹配依据。
- 完成可靠检索后确实没有合适岗位，展示“未投递：没有符合职位”，附原因、来源与时间，结束本公司本批次任务后自动处理队列下一家，不填凑数岗位。
- 登录失效、网页打不开、没有权限、检索不完整或资格无法确定，记为“待处理／检索受阻”，**不能冒充没有岗位而跳过**。
- 普通未知字段只暂停该字段及依赖它的操作，不反复打断整个任务。这里的“填写完成”指完成全部可安全填写的内容，不代表未知字段也会被猜填。
- 主流程必须由程序状态机、迁移表和校验条件执行，不能只放在聊天上下文或长 Prompt 里期待模型记住。模型只处理当前节点的有限任务，不能自行跳步或宣告整个公司完成。

## 1. 文案来源：先确认，再复制

1. 用户从自己认可的简历提供文本；可选本地离线解析只生成候选段落，不上传第三方，不作为已确认信息。
2. 本地解析识别个人信息、教育、实习、项目、技能、语言和评价区域；公司、地点、岗位、日期与正文分别保存。未可靠识别的字段保持空白，原文保留。实习正文不生成新内容。
3. 用户手动调整格式、所属经历、栏目及段落，逐块确认。项目内容和项目职责必须分别确认。
4. 填写时模型只能选择正确的已确认块，填写程序按文本原样执行。完整保留句子、数字、技术名称、段落顺序及空行；允许导入及系统剪贴板往返时统一 CRLF / CR 为 LF，除此之外不得静默更改。
5. 不自动压缩、润色、翻译、补全、概括或截断。网页排版不能表示原格式时记录限制，不改文案冒充原样。
6. 用户最新授权：准备阶段可以基于项目原文推导简述／职责候选，必须标注出处及未确认状态，保留原文中的验证限制，也可由用户后续提供。不能添加无依据技术、夸大本人贡献，不能默认「独立开发」角色。无可靠依据时请本人补充。
7. 网站限制长度时先检查；超限交用户调整。短版也必须由用户单独确认后才能使用。
8. 填后读回对比确认文本；网站清洗或截断产生差异时标记失败，不能称原文填写完成。

项目简述说明项目做什么；项目职责说明本人使用哪些技术完成哪些工作。准备阶段的推导候选与原始正文分开；只有本人确认后的版本才能复制填写。没有个人评价时不顺带生成评价。

## 2. 单家公司循环（后续实现）

- [ ] 接收链接与可选内推码，保留来源及码候选，进入待完成任务池；导入不是开始运行、登录或提交授权。
- [ ] 复用用户指定的官方页面，本人完成登录与验证码，不读取登录凭据。
- [ ] 先查本地记录，再查官网申请记录；区分公司主体、招聘批次、岗位 ID。范围不足时标记未知，不断言从未申请。
- [ ] 检查当前毕业窗口、海外学历认证规则和用户已确认毕业时间；系统允许填写不等于符合资格。
- [ ] 核查总额度、已用、剩余、同集团限制、志愿流转顺序与修改规则。多意向不等于多次申请，不提交测试额度。
- [ ] 根据当前官方 JD、硬性资格与已确认资料，返回 1～3 个候选；每个包含岗位 ID、城市、来源链接、查询时间、匹配证据、缺口及待核规则。不编造匹配百分比，不猜竞争人数。
- [ ] 等本人选择岗位并确认优先级；执行前再检查岗位是否有效、历史申请及额度是否变化。不因优先级获准而代提交。
- [ ] 建立字段计划并冻结资料、岗位顺序和角色模型配置的版本。模型只选择事实及已确认段落；确定字段通过程序精确查询，不逐字段调用模型。
- [ ] 先确认附件与上传是否触发解析，再安排填写顺序；不依赖网站解析提取事实，不重复重传。
- [ ] 按已确认计划批量填入并上传要求的简历、照片；核验版本、格式、大小和实际上传结果。
- [ ] 批量读回并比较。位置、岗位名、实习职责、项目内容、项目职责不混用。控制重复经历定位，不按空框猜字段。
- [ ] 将缺失、冲突、超长和不明字段写入持久化问题队列；继续其他无依赖的安全字段，未知声明不默认选否，不绕过网站校验。若未知项阻止下一页，记录访问不到的区域，先完成当前可达内容，再集中请求处理。
- [ ] 自动运行程序检查和独立模型 review；必须对照实际页面读回值、已确认资料及当前 JD，而不只是复核本地清单。复核者只读，不同时修改表单。
- [ ] 首轮填写和 review 结束后，合并去重问题并集中弹出；本人回答后，仅恢复相关字段及依赖步骤，必要时重新确认资料，再读回并复核。仍有阻断问题不得标为可提交。
- [ ] 输出送审单，停在最终提交之前，由本人审核并点击提交。
- [ ] 本人提交后只读核验申请记录；本人报告与官网核验分开保存。处理同公司下一适合岗位，再进入下一公司。
- [ ] 结果写入后由程序生成“已投递：岗位名称”等状态；所有已选岗位均达到本节末尾的队列完成条件时，自动开启下一家公司，不反复询问是否继续。不自动点击最终提交。

## 3. 模型能力范围

可以：理解字段语义、识别 JD 条件、基于证据匹配排序、准备阶段生成带来源的项目简述／职责候选、选择确认段落、解释异常与生成审核清单。

不可以：填写阶段临时生成或改写实习／项目文案、跳过本人确认使用候选、臆测经历技术和声明、保证未知网站零错误、把未知规则当已核实、代登录/验证码/最终提交、撤回删除重投、把个人在线简历更新当已投快照更新。

## 4. 工程约束

- 固定事实走精确查询；RAG 只补充相关经历证据和规则，不跳过版本和冲突检查。
- 工具层执行权限校验；禁止依靠 Prompt 作为唯一权限边界，不给填表模型无限制点击和脚本执行权限。
- 保存按钮含提交作用或语义未知时不能点击。审核通过不改变本人最终提交边界。
- 一张页面一个写入者；本人编辑时代理暂停，不刷新关闭未保存表单。
- checkpoint 不等于网站草稿；恢复时重新观察现场，幂等处理上传和添加经历，避免重复操作。
- 字段状态、草稿状态和提交状态分开记录。工具无报错不等于网站保存成功。
- 敏感数据只在本地必要使用；云模型与 embedding 接口另行授权和脱敏，不默认上传整份资料库。

## 5. 最低验收集

- [ ] 普通字段批量处理，比逐字段模型调用减少往返，实际记录耗时与人工修改数。
- [ ] 已确认文案复制、填写、读回逐字符一致，不截断超长内容。
- [ ] 字段错配、过期资料、GPA 冲突、重复申请和毕业窗口不符得到拦截。
- [ ] 上传触发覆盖、日期未真正更新、无后台保存证据不能错误报告成功。
- [ ] 用户编辑、中断恢复不会重复创建经历或覆盖本人修改。
- [ ] 所有最终提交、登录与验证码动作仍由本人执行。
- [ ] 只有 1 个合适岗位就返回 1 个；没有岗位与检索失败、登录受阻明确区分；岗位优先级不突破志愿额度。
- [ ] 普通问题不会逐项弹窗阻断；填写和复核问题合并后一次展示，处理结果刷新及恢复后仍在。
- [ ] 角色使用本人保存的模型配置，失败不会静默切换到其他提供商或扩大资料发送范围。
- [ ] OpenChamber 内可以完成任务导入、岗位选择、查看问题和恢复；无需手工启动独立预览服务器。
- [ ] 清空对话上下文、切换模型或重启后，可从持久化状态和重新观察的网页恢复；缺少证据的步骤不自动跳过，危险动作不重放。
- [ ] 已投递记录无需模型重读历史聊天；重复公司／岗位不会重填重投。家庭资料不会因岗位检索被整批发送，发布产物及暂存文件不含真实私有信息。
- [ ] 多岗位公司只完成其中一个时不进入下一家公司；整家公司完成或经可靠检索确认无合适岗位后，下一公司只启动一次。队列暂停、待登录和安全阻断有效。

## 6. 任务池与问题弹窗（设计，未实现）

### 6.1 用户看到什么

- 任务池：待登录、检索中、待选岗位、填写中、复核中、待你处理、待你提交、待核验、已核验、已跳过，以及暂停／失败。
- 状态与困难用短提示、角标和可展开详情显示；普通进度不弹阻断窗口。
- 每家公司可执行部分处理结束后，出现一张“需要你处理”的汇总弹窗。跨公司未决项也能在问题中心查看，但不能因此同时写同一表单。
- 汇总按“必须补充／待确认／建议”分组，能跳到对应任务与字段；支持填写、选择、稍后处理、跳过任务。关闭弹窗只隐藏，不清除问题、不自动确认。
- 登录、验证码、权限不足、可能提交／扣额度、覆盖本人修改、意外资料外发等必须立即停下受影响操作并提醒；不能为了少问而跳过安全与权限检查。

### 6.2 问题必须能恢复，不只是聊天记录

每项问题记录：任务与岗位 ID、区域与字段稳定 ID、问题类型、可读说明、可验证依据、影响范围、可选处理方式、状态、本人回答和确认版本、创建及更新时间。只展示简短原因与证据，不要求或存储模型隐藏推理。

同一字段在填写和 review 中重复出现时合并；解决后标记已解决，不丢历史。本人回答不自动推广为跨公司个人事实，跳过也不等于官网已填写。页面重载或模型超时后，重新观察网页再恢复，不重复上传或创建经历。

## 7. 固定角色模型（设计，未实现）

| 角色 | 用户可选配置 | 权限 |
|---|---|---|
| 信息检索与岗位匹配 | 例如 DeepSeek；供应商／模型由本人选择 | 只读官方页面与按需提供的资料，输出候选与证据 |
| 填写执行 | 例如 DeepSeek，可与检索共用也可分别指定 | 只操作当前已授权字段计划，不代提交 |
| 独立 review | 例如 GPT 或本人选择的其他模型 | 独立上下文，只读资料与页面快照，输出问题及差异 |

设置保存提供商、精确模型 ID、凭据引用、可选推理档位、费用／调用预算及经本人批准的失败策略；不硬编码产品名为可调用 ID，不把 OpenCode 编码会话当前模型当作业务默认授权。支持从可用模型选择，或按后端支持填写自有接口；不要求本人在聊天中提供 Key。

每次运行保存角色配置快照和实际模型标识；修改配置只影响明确恢复或新启动的步骤。模型不可用时进入待处理，不暗中升级到高价模型或换服务商。review 超时、解析失败或未运行都不能显示“检查通过”。

选择云模型意味着相应最少必要资料会发送给该提供商，须事先说明并取得授权；不默认发送整份简历、全部公司清单、登录凭据或无关敏感字段。

## 8. OpenChamber 内使用（目标形态，未实现）

首选 **OpenChamber 扩展**，不是把现有 Chrome 扩展改个名字，也不是只在浏览器面板打开在线 demo。

- 用官方 `@openchamber/sdk` 提供侧栏任务池，可选全屏看板；使用扩展自己的任务选择／问题对话框与宿主 toast、角标进行提醒。
- 前端随扩展打包，由宿主加载；日常无需运行 `npm run serve` 或手动打开 localhost。OpenChamber／OpenCode 和授权后的执行连接层仍在后台运行，不宣称零后台进程。
- OpenChamber 扩展负责交互；OpenCode 插件／受控服务负责持久化编排、角色模型调用和权限校验；浏览器工具及首个平台适配器负责网站操作。具体传输和兼容版本在实施前核验。
- 官方 `host.prompt` 使用当前会话已选模型，`host.generate` 使用宿主 Small Model，均不能直接满足任意多角色模型路由。不能仅加模型下拉框就声称分工已实现；路由应由明确授权的后端连接实现。
- 招聘官网是独立浏览器页，用户在该页登录。桌面内置浏览器是否可驱动、是否能满足上传和完整读回，必须逐项验证；不足时另行批准 Playwright／CDP 适配，不绕过登录或把网站塞进扩展 iframe。
- 用户已选择 **Moka** 为首个平台。选择平台不授权登录、提交或使用真实简历测试；具体页面、自定义控件、上传与跨页支持须分项验证，不承诺整个 Moka 平台通用。
- 扩展面板文档支持 web 与 desktop；内置浏览器自动操作以 desktop 为起点，web 端不能仅凭面板可见就声称可自动填表。VS Code／移动端不作为本轮承诺。
- 任务、问题、确认版本与快照以本项目 `private/` 下的显式数据文件为目标事实源，由单写入后端管理；不依赖聊天记忆或会话 idle 判定完成。宿主存储只放必要 UI 偏好与引用。现有浏览器数据迁移需本人确认，不能自动合并或清空。
- 所连 OpenChamber 服务器的部署地点决定宿主存储地点；远程实例不是本机。宿主安装副本、凭据和浏览器缓存可能位于其自管目录，必须如实披露。

## 9. 固定流程、私有资料与顺序队列（已确认需求，待实现）

### 9.1 流程不靠聊天记忆

- 状态机与合法迁移写在程序／版本化配置中；每个节点规定入口条件、允许动作、结构化输出、退出条件及失败去向。
- 编排器决定下一步，模型不决定流程。模型输出通过 schema、资料确认版本、作用范围、权限及页面证据校验后才可用于迁移；JSON 合法也不代表网站已保存。
- 每次迁移持久化当前任务、岗位、节点、资料及模型配置版本、完成凭据、未决问题和下一可执行动作。正常执行不需要反复读取整段聊天、长期记忆或全部历史记录。
- 模型仅收到当前节点必要输入、必要安全约束和相关字段，不把完整流程和全部个人资料反复塞进上下文；代码守卫才是权限和流程边界。
- 程序缓存已读取版本，在任务开始、版本变化、恢复或有证据需要更新时精确读取。不能为了减少读取而继续使用失效的确认、过期岗位或过时额度。
- 所谓“固定”是合法流程固定，不是无视现场强行继续。登录、人工回答、review 失败、资料变更均有明确等待或重检分支。

### 9.2 私有资料结构化、按需调阅

目标将个人信息、教育、实习、项目、技能、家庭成员／父母资料、附件版本、公司专属回答分区保存于本项目 `private/`。运行记录、问题和网页证据也属私有数据，不能出现在公开示例、fixture、日志、文档或发布包中。

每条事实／段落保存稳定 ID、字段类型、所属经历或家庭成员 ID、原文或精确值、来源引用、版本、确认状态／时间、适用范围、敏感等级。项目内容与本人职责分开；未知值保持未知，不从姓名或关系推断其他资料。

模型通过受控查询获取当前用途需要的字段，例如按经历 ID 查询项目职责。后端程序可直接填确定字段时不必把值交给模型；父母信息只在真实表单明确要求且本人授权时读取／发送，不用于普通公司或岗位检索。长期保存以本人选择为前提，不要求提前提供全部家庭资料。

GitHub 只接收代码、通用文档、空 schema 和虚构示例。`private/`、运行数据、附件、截图、缓存、导出和凭据不进 Git；除忽略规则外，还须在暂存与打包发布边界检查允许文件及内容，不能把 gitignore 当作防泄露的全部保障，也不能假设已被跟踪的文件会自动受其保护。不擅自清理历史或删除用户文件。

“不上传 GitHub”不等于“不会发送给云模型”：使用 DeepSeek／GPT 时仍须单独说明最少必要字段会发往哪里，取得相应授权，避免敏感值进入普通聊天和调试日志。

### 9.3 投递台账是状态来源，不让模型回忆

| 实际记录 | 用户看到的结果 | 是否允许自动重投 |
|---|---|---|
| 本人已提交，官网已查到对应申请 | 已投递：岗位甲、岗位乙（官网已核验） | 否 |
| 本人明确报告已提交，尚未官网核验 | 已投递：岗位甲（本人记录，待官网核验） | 否；核验不足不成为再次提交的理由 |
| 完成可靠检索，当前批次无合适岗位 | 未投递：没有符合职位 | 本批次本轮不重复检索；过期／新批次或本人要求时重新核查 |
| 填写或 review 已完成，尚未本人提交 | 待本人提交：岗位甲 | 否，不得标已投递 |
| 登录失效、检索失败、岗位资格不明 | 待处理：具体原因 | 不当作无岗位或成功 |
| 只完成部分已选岗位 | 部分已投递：岗位甲；待处理：岗位乙 | 不重投岗位甲，不自动假称公司全部完成 |

状态文案由结构化记录确定性生成；记录申请人、公司主体、批次、岗位 ID／名称、优先级、提交状态、核验状态、时间及证据来源，任务阶段与投递结果分开保存。正常只按索引查当前公司／岗位，无需每次让模型翻历史聊天。新批次、不同岗位及共享志愿需单独判断，不能仅按公司名永久跳过。

### 9.4 一家公司处理完，再自动取下一家

- 本人启动队列时授权其顺序推进范围，可暂停／恢复／停止。默认按入队顺序，每次一个活动公司；公司内按本人确认优先级处理岗位，并遵守官网志愿、共享资料和额度限制。
- 某个所选岗位待补资料、待 review、待本人提交或提交结果不明确时，不能以“公司已完成”推进。无需提交的岗位必须有明确官网证据或本人选择的跳过原因，不能静默丢弃。
- 全部已选岗位均为“官网核验已提交”或“本人明确报告已提交”（后者继续保留待核验标记），且不存在影响提交真实性的阻断问题时，记录公司完成，再自动取下一家公司；共享志愿的一次提交须关联实际覆盖的岗位，而非重复提交。
- 确认没有合适岗位后记录对应终态并自动取下一家。本人明确跳过整家公司也可推进，但显示其真实原因，不写成“没有符合职位”。
- 本人最终提交、登录及验证码始终人工执行；自动切换公司不扩大这些权限。下一家公司未登录时进入待登录，而不是尝试读取凭据或绕过验证码。
- 队列游标、活动任务、占用锁和完成事件持久化；重复回调不启动两次下一家公司。崩溃后的不确定操作先核验，不把“待重试”变成重投，也不自动关闭未保存表单。
- 有未决问题时默认保留当前公司并集中提醒；若本人选择“暂放，继续下一家”，记录挂起及恢复位置，不标记完成。终态公司不因弹窗关闭、会话 idle 或模型自述而变化。
