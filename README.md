# Application Copilot

本地求职申请准备助手。先解析并审核简历资料，再受控填写；准备阶段可推导项目候选，填写阶段只复制确认文本，不靠招聘网站解析、不临时改写经历、不代最终提交。

## 项目目标与完整流程

目标不是自由操作浏览器的自动海投，而是把重复填表交给程序，把岗位理解和异常判断交给模型，把事实确认、登录及最终提交留给本人。

```text
一次性准备：本地解析简历区域与经历字段 → 项目简述／职责候选或本人提供 → 本人调整确认 → 固定段落及材料版本

单家公司：
官方页面／本人登录
  → 查历史投递，避免重复申请
  → 核实毕业窗口、海外认证规则及真实志愿额度
  → 根据当前 JD、本人经历和偏好推荐志愿顺序
  → 匹配网页字段，选择确认事实与原文段落
  → 批量填写，按要求上传简历和照片
  → 读回比对、保存状态核验、汇总缺失和风险
  → 停在最终提交前，由本人检查并提交
  → 只读核验投递结果，记录后推进同公司下一岗位／下一家公司
```

**以上是目标流程，不代表当前版本已全部实现。** 当前可用本地 DOCX／文本解析、结构化字段预览和离线段落库；公司核查、岗位排序、网站自动填写和模型接口仍待开发。

## 目标架构与模块分工

| 模块 | 责任 | 当前状态 |
|---|---|---|
| 本地段落库 | 用户调整、分类、逐块确认，原文复制 | 已实现基础版 |
| 本地简历解析 | 个人信息、教育、实习、项目、技能、语言和评价分区，字段与正文分离 | 已实现规则版，需本人核对 |
| 事实与材料库 | 确认事实、来源、冲突、简历与照片版本 | 待开发 |
| 公司与申请记录 | 主体／批次／岗位识别，历史去重和状态区分 | 待开发 |
| 招聘规则与岗位匹配 | 官方资格、志愿额度、JD 证据与优先级 | 待开发 |
| 网站适配器 | 稳定定位、批量填写、附件上传和读回比对 | 待开发 |
| 工作流与人机协作 | 中断恢复、页面单写入者、本人审核及结果核验 | 待开发 |

计划采用浏览器扩展＋本地服务，先适配一个招聘平台，再扩展。准备阶段允许基于原文推导项目简述／职责候选，保留出处并等待本人确认，不新增技术或贡献。填写阶段模型只理解页面、选择已确认资料、判断岗位匹配和解释异常，程序执行确定字段填入和校验，不逐字段反复决策、不临时改写正文。

技术接入按实际需要推进，以下尚未实现：

- **LangChain**：模型接口、结构化 JD／字段映射输出、受限检索与工具封装；如接项目候选生成，必须在准备阶段且经本人确认，不在填表时改写。
- **LangGraph**：显式状态、条件分支、持久化和人工中断；恢复后仍需重新检查招聘网页。
- **RAG**：按来源、有效状态、公司／批次检索相关经历证据和招聘规则。固定事实、附件版本、申请状态优先精确查询，不逐字段做向量检索。
- **浏览器执行层**：扩展站点适配器为主，必要时接本地 Playwright；填写模型不获得无限制点击、任意脚本或最终提交权限。

## 不可变更的工作边界

- 不用招聘网站解析简历来提取填写资料；附件上传单独管理，强制解析时先识别覆盖风险。
- 填写只用本人确认段落，保留文字及空行，不临时重写、翻译、压缩或截断。准备阶段允许由原文推导项目简述／职责候选，标注出处及未确认状态，也可由本人后续提供。
- 地点、岗位、实习内容、项目内容和本人职责分别映射，不能按空输入框顺序猜测。
- 资格和额度未知就标未知，不以系统允许填写或多选意向推断符合资格或可多次投递。
- 不代登录、验证码或最终提交，不撤回、删除或重复申请；本人审核通过也不产生代提交权限。
- 页面已填、草稿已保存、本人报告已提交和官网核验已提交分开记录。真实资料不进 Git，外部模型接收资料需要另行授权和最小化。

## 当前可用：本地解析与离线段落库

1. 在 Chrome / Edge 扩展管理页开启开发者模式，选择「加载已解压的扩展程序」，加载本目录的 `extension` 文件夹。
2. 点击扩展图标，打开段落库编辑器；也可用本地静态服务器打开编辑器测试。
3. 导入本地 DOCX、TXT、Markdown，或粘贴 PDF 已提取文本，再点击「自动解析简历区域」。DOCX 在本地读取正文和页眉，不上传服务器、不依赖招聘网站解析。
4. 检查个人信息、教育、实习、项目、技能、语言和评价。实习公司、地点、岗位、日期与正文分别保存；缺失字段保持空白，项目岗位不默认独立开发。PDF 折行仅重建为候选，完整原文保留供核对。
5. 点击「将结构化正文加入段落库」；可选择同时加入有原文出处的项目简述／职责候选。内置程序采用规则与原文摘取，不是云模型推理，简述和职责可能重复。用户可以修改或另行提供；外部 Agent 按授权推导的候选也必须标为未确认。
6. 手动调整段落，项目原文、项目内容和项目职责分别保存。需要保留多段时，可在同一块内编辑并留空行。
7. 每块单独勾选确认并保存，再点击复制。任何修改都会取消该块确认；复制严格使用确认文本，不压缩、不润色、不截断。
8. 若网站有限字数，可先输入上限。超限时拒绝复制，请用户返回编辑，不自动删改。该检查按浏览器 UTF-16 长度计算，实际网站可能另有计数规则。

支持导出／导入本工具的结构化 JSON，重新导入一律保持未确认。项目的缺少职责、未完成评测、模拟验证等限制不得因为生成候选而删除。

复制保留正文、顺序和空行。Windows 系统剪贴板可能将 LF 转成 CRLF；网页文本框粘贴后通常恢复为 LF，核验只允许这种换行编码归一化，不允许改动文字或段落。请只打开一个编辑器页面整理资料，避免不同标签同时编辑产生覆盖。

资料仅保存于当前浏览器本地存储（不加密），不上传服务器，也不读取招聘页面。公用电脑不建议保存敏感资料；清空按钮删除本扩展的段落及解析简历，但不清除剪贴板或已导出文件。本扩展无遥测，无模型调用，无站点权限。点击自动解析后，完整提取原文也保存在本地用于核对；请不要导入密码、验证码、身份证等不必要的信息。DOCX 只处理 Word 正文及页眉文字，不执行宏、嵌入对象或外部实体；复杂表格、文本框、扫描件和其他排版仍需本人检查。

**当前不是完整自动填表插件。** 尚未实现 PDF 二进制解析／OCR、岗位检索、网站字段映射、自动照片上传、申请状态核验或模型接口。PDF 可粘贴已提取文字；当前支持本地 DOCX 与文本的常见结构，不保证任意简历版式都准确。

## 开发与测试

无需安装第三方依赖，Node.js 22+：

```text
npm test
npm run serve
```

静态测试页：`http://127.0.0.1:4173/extension/editor.html`。普通网页运行时使用浏览器 localStorage，与扩展存储相互隔离。

也可离线生成结构化 JSON，默认输出到 Git 忽略的 `private/`，已有文件不会覆盖：

```text
npm run parse-resume -- "本地简历.docx" "private/resume-parsed.json"
```

随后在编辑器导入该 JSON。CLI 和编辑器均不把导入结果视为已确认事实。
